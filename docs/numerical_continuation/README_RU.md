# Численное продолжение BQG — 12 октября 2026

Этот пакет содержит исправление конечной проверки K5, выбранный слабый матричный элемент структурного H_L-кандидата и начало следующей стадии. **Физический предел, полное лоренцево семейство и полный бюджет ошибок не доказаны.**

## Результаты

- Исправленный K5 использует нормированные столбцы, относительный SVD-порог и прямой остаток. Конечный запуск проходит: ранг Wilson–Krylov равен 1, остаток равен 1/91 в floating point. Это не точный сертификат ранга.
- Для нового выбранного входа завершены 26/26 внутренних HE-образов и 16/16 компонент CK. Все сохранённые заряды согласованы; внутренняя SU2-ковариантность проверена.
- Выбранный обратный элемент в слабой форме примерно равен 0.0846355393325926 i; расхождение с прежним сопряжённым элементом около 1.94e-16. Перенос факторов использует явно заданные primitive-adjoint identities; это не прямое последовательное исполнение reverse-колонки.
- Подготовлены 96 входов второй CK-стадии. Для её **прямой части** требуется 352 канонических HE-входа; первые три вычислены. Полных вторых CK-действий пока 0/96. Дополнительные inverse-holonomy требования ещё не включены в число 352.

## Воспроизведение

Из корня репозитория:

```bash
python -m unittest discover -s tests
python docs/numerical_continuation/verify_results.py
```

Три выбранных локальных блока объёма можно заново вывести символически (требуется SymPy):

```bash
python docs/numerical_continuation/verify_volume_blocks.py
```

Вторая команда требует только стандартную библиотеку. Она проверяет SHA-256 архива, читает сохранённые JSON-векторы, точно восстанавливает binary64-коэффициенты из float.hex и заново считает слабые суммы. **Она не регенерирует микроскопические амплитуды.** Архив также содержит 96 следующих входов и две исходные внутренние HE-контрольные точки; третья сохранена отдельно в ADDITIONAL_SECOND_STAGE_HE.json. JSON читается без pickle/deserialization кода.

Для отдельного повторения одного HE-образа требуются NumPy/SciPy/SymPy и другие зависимости используемого backend:

```bash
OPENBLAS_NUM_THREADS=1 python docs/numerical_continuation/recompute_first_HE.py --output /tmp/bqg_HE_recomputed.json
```

Это более тяжёлый расчёт. Перед ним проверяются хеши локального Python backend. Экспериментальное продолжение объёма устанавливается только в процессе этой команды; исходники production backend не переписываются. Нельзя считать его физически выбранным объёмом BQG только из-за успешной проверки.

## Области применимости

Скрипты используют один источник, node0, структурную нормировку κ=1 и doubled-spin wall=7. Число complete означает завершение конкретного конечного перечисления. Максимальная branch-leakage не равна ошибке полной суммы; её компенсация проверена лишь на одном расширенном HE-образе. Оценка 9.4e-12 покрывает только накопление уже вычисленных коэффициентов при указанных floating-point предпосылках. Ошибки генерации, multiplication, pruning и предел уточнения отдельно открыты.

Источники: frozen script commit 54c5d907 и отпечаток старого кандидата 32b0756b…; новые файлы и SHA-256 перечислены в MANIFEST.json и BACKEND_MANIFEST.json. Полные исторические запуски этим пакетом не повторяются.

## Продолжить вторую стадию

```bash
OPENBLAS_NUM_THREADS=1 python docs/numerical_continuation/continue_second_stage.py --output-dir /tmp/bqg_second_stage --max-new-he 2
```

Команда восстанавливает три опубликованные контрольные точки и считает до двух следующих прямых HE-образов. Повторный запуск переиспользует JSON в выбранном output-dir. `--max-new-he 0` проверяет подготовку без новых HE-вызовов. Это только прямая часть второй CK-стадии; полные 96 CK-действий и обратная HL-колонка ею не завершаются. Используйте отдельный output-dir для данного pinned backend; для изменённого оператора требуется новый набор контрольных точек.
